# Prompter Tablet Android prototype

Native Kotlin/Jetpack Compose client for the portrait-mounted Samsung Galaxy Tab A8 SM-X200. Windows remains authoritative for manuscript, transcription, alignment, and semantic movement. Android performs no alignment or transcription.

## Toolchain

- JDK 17 or newer supported by Android Gradle Plugin 9.2
- Android SDK Platform 36 and Build Tools 36.x
- Android SDK Platform Tools (`adb`)
- Gradle 9.6.1 through the checked-in wrapper

From the repository root:

```powershell
npm run android:test
npm run android:assemble-debug
npm run android:lint
npm run android:install-debug
```

Set `ANDROID_HOME` or create untracked `android/local.properties` containing `sdk.dir=C:\\Users\\you\\AppData\\Local\\Android\\Sdk`.

## Protocol mapping

The JSON Schemas in `../shared/protocol` remain authoritative. `ProtocolModels.kt` maps the common envelope and current payloads using `kotlinx.serialization` with unknown optional fields ignored. Gradle copies the existing positive and negative JSON fixtures directly into Android unit-test resources; they are not forked.

HMAC input is UTF-8 text joined exactly as Windows implements it:

```text
challenge|clientNonce|serverId|deviceId|protocolMajor
```

The result is SHA-256 HMAC encoded as unpadded base64url. Unit tests use a vector generated by the Windows `AuthenticationService`.

## Trusted-LAN limitation

Android's network security XML cannot express RFC1918 CIDR ranges. Cleartext is enabled for this prototype at the manifest layer, while `PrompterConnectionRepository` refuses non-private IPv4 destinations before opening `ws://`. This is access scoping, not confidentiality: manuscript and microphone audio remain visible to a capable observer on the LAN. Certificate-pinned WSS is required before wider distribution.

USB mode reuses the same authenticated protocol through `adb reverse`; it is not a second unauthenticated control path. The only loopback endpoint accepted comes from a fixed explicit action/component with validated server-ID, integer-port, and mode extras. The desktop normally discovers and launches it automatically. An authenticated USB candidate is promoted before the old LAN socket is retired, while socket/audio generations fence stale traffic.

## Physical SM-X200 workflow

1. On the tablet, open Settings → About tablet → Software information and tap Build number seven times.
2. Enable Developer options → USB debugging.
3. Connect USB, accept the tablet authorization prompt, and run `adb devices`.
4. Run `npm run android:assemble-debug`.
5. Run `npm run android:install-debug`, or `adb install -r android/app/build/outputs/apk/debug/app-debug.apk`.
6. Launch **Prompter Tablet**.
7. On Windows, open Prompter and enable **Server On** in the tray. Approve Windows Firewall only for Private networks if prompted.
8. Select the discovered PC. Use **Pair** and approve the Windows dialog; alternatively enter the active six-digit tray code.
9. Open a manuscript on Windows and wait for the snapshot to appear on the tablet.
10. Grant microphone permission, tap **Start microphone**, narrate, and verify transcript and semantic scrolling.
11. Disable/re-enable Wi-Fi or restart the Windows server and verify reconnect/snapshot restoration.

The server normally starts off after each Windows launch; detection of one stable authorized USB tablet enables it automatically. The LAN path uses DNS-SD `_prompter._tcp.local.`; manual private address and port 43127 are fallback only. VPN/virtual adapters on Windows may advertise an address the tablet cannot reach.

For USB verification after the tablet has been paired once, leave Prompter Tablet installed and USB debugging enabled, connect one authorized tablet, and start the desktop build. The desktop uses tablet-local port 43128 by default and enables its server automatically after the cable is stable. Do not run a manual `adb reverse` at the same time. Advanced diagnostics shows ADB/device/tunnel state and permits LAN-only or USB-only troubleshooting.

The separate Vocal review APK uses application ID `app.prompter.tablet.vocalcandidate`; its launchable activity class remains `app.prompter.tablet.MainActivity`. The Vocal desktop candidate selects that explicit component, listens on desktop port 43129, and uses tablet-local reverse port 43130 with `adb reverse --no-rebind`. The ordinary package and ports 43127/43128 are unchanged. For an isolated review, set `PROMPTER_USER_DATA_DIR` to a disposable candidate data directory, set `PROMPTER_ENABLE_TABLET=1`, and leave `PROMPTER_DISABLE_TABLET` unset for that desktop process only. Keep the normal installed desktop and tablet data separate.
